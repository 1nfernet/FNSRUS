# FNSRUS 1.0

Дата: 13 октября 2026 года. Git-тег: `1.0`. Версия приложения: `VERSION`.

## Назначение

Браузерный инструмент проверки российских контрагентов: русскоязычная карточка,
обзор рисков и покрытия, копирование данных и полный исходный JSON. Работает
без LLM, поверх закреплённого MCP-сервера; API-ФНС подключается по желанию.

## Состав релиза

- Исходники приложения, `requirements.txt` и файл `VERSION`.
- Локальные иконки/шрифты с их лицензиями.
- Конфигурации systemd/Nginx и пустой `.env.example`.
- Тесты и GitHub Actions CI на Python 3.12.
- Документация API, установки, происхождения и история изменений.
- Настольный, мобильный и settings-скриншоты без API-ключа.
- Исходные архивы `FNSRUS-1.0.tar.gz`, `FNSRUS-1.0.zip` и `SHA256SUMS.txt`
  в GitHub Release. Архивы создаются из коммита тега, не из рабочей папки сервера.

Ключи, `.env`, SQLite, логи, `.venv`, `.git`, staging и резервные копии
не публикуются. Скриншоты показывают интерфейс, а не обещание полного покрытия.

## Проверка

24 теста покрывают транспорт MCP, семь имён инструментов, лимиты, занятость,
таймауты, сохранность JSON, версию, настройки ключа, ссылку регистрации,
реальный формат `stat`, приватность журналов, отказ по IP, обогащение и сохранение
критичных вердиктов. Обычный запуск использует mock-транспорт для платного API;
живой открытый источник включается через `FNS_LIVE_TESTS=1`.

```bash
python -m unittest test_server -v
```

На установленном сервере проверяются служба, Nginx, HTTP health, права приватного
файла настроек, версия и соответствие исходников. Реальный ключ `stat` проверен
после исправления разрешённого IP; дополнительные платные проверки в регрессиях
не выполняются. Снимки интерфейса проверяются на настольном и мобильном viewport.

Снимки сделаны 13 октября 2026 года на реальной карточке ПАО Сбербанк
(ИНН `7707083893`): [desktop](screenshots/desktop.png), 1440 x 1200;

## Продакшн

Поддерживаемая конфигурация 1.0: Ubuntu 24.04, Python 3.12, один Uvicorn worker,
loopback backend, Nginx, systemd, 512 МБ RAM и ограничение 80% CPU для приложения.
Инструкция: [deployment.md](deployment.md).

Текущая конфигурация готова для доверенной LAN, не для открытого Интернета.
До публичного запуска необходимы TLS и авторизация на reverse proxy, ограничение
административного доступа, закрытый порт backend, мониторинг и приватное
резервирование настроек/реестров. В приложении нет собственной авторизации.
На HTTP секрет от браузера к серверу не шифруется. Проект не выдаёт такую установку
за безопасный публичный сервис.

API-ФНС в бесплатном тестовом режиме разрешает один внешний IP и ограниченный
бюджет запросов. Укажите в кабинете внешний IP сервера. При изменении адреса
снова обновите привязку. Метод `stat` не заменяет проверку доступности иных источников.

## Обновление и откат

Перед установкой тега сохраните исходники и конфиги для отката. Приватный файл
ключа и базу реестров резервируйте отдельно, не в публичный исходный архив.
Установите полный состав тега, включая `api_fns.py` и `VERSION`, проверьте тесты
и синтаксис конфигов, затем перезапустите службу и проверьте HTTP-готовность.
Для отката восстановите предыдущие исходники/конфиги без удаления рабочих данных.

Ветка репозитория - `master`; тег `1.0` и выпущенные архивы являются
зафиксированным снимком. Новые изменения получают новый тег, существующий тег
не перемещается и push с `--force` не используется.
